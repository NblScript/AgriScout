# 核心信念：代理优先操作原则

> 借鉴 OpenAI Harness Engineering 的文档方法论，结合本仓库实际沉淀。
> 这些原则优先级高于个人偏好；与 docs/05 冲突时以 05 为准（它记录「为什么」，本文记录「怎么做」）。

## 1. 仓库即记录系统

代理运行时看不到的内容等于不存在。聊天结论、头脑方案、白板讨论，不落盘就会丢。
- **做法**：跨会话知识三去处——决策进 `decision-registry.md`，进行中的工作进 `exec-plans/active/`，
  表结构进 `docs/generated/`（脚本生成）。
- **反例教训**：D 系列决策定义曾随旧文档清理而佚失，代码注释却还在引用「基线 D5」——
  2026-08 靠 git 考古才补回。这就是「记录系统」断层的真实代价。

## 2. 地图，而非说明书

AGENTS.md 保持 ≤120 行，只做导航与红线；细节按需渐进披露。
- 当一切都「重要」时一切都不重要——巨型指令文件会挤掉关键约束的注意力。
- 校验是机械的：`backend/tests/test_docs.py` 会拒绝超行数的 AGENTS.md。

## 3. 偏好枯燥技术

可组合性、API 稳定性、训练语料覆盖都比新鲜感值钱。
- 本仓库的印证：FastAPI + SQLAlchemy + Alembic + Element Plus + Leaflet + ECharts，
  全是主流轮子；Leaflet 刻意用原生封装而非 vue-leaflet 包装库（M6 决策：依赖少、行为可控）。
- 自研小函数胜过不透明依赖：EChart.vue 30 行封装替代 vue-echarts；
  颜色统计 60 行纯 Python 撑起 L0 占位识别。

## 4. 执行计划是一等公民

非常规改动先写计划再动手，计划提交进仓库：
- 小改动：一句话在 commit message 里说清即可，不必建文件
- 复杂工作：`exec-plans/active/` 建计划（状态/决策记录/进度三节必有），完成移 `completed/`
- 计划是给「下一个接手的会话」看的——写它的时候假设读者没有任何本次对话的记忆

## 5. 品味编码化：强制不变量，而非微观管理

能变成代码的规则就不要只写在文档里：
- pytest 守护：38 个后端测试 + `test_docs.py` 文档校验
- gitignore 守护：`*.pt`/`*.db`/`media/`/训练产物永不入库
- 协议守护：`patrol-schema` 端点导出 JSON Schema，模拟器与小车端以此为合同
- 唯一事实源：规则在 YAML、类型在前端 `types.ts`、表结构在 models——先改源头，派生物重新生成

## 6. 里程碑即历史

一个里程碑一个 commit（`M{n}: 主题——交付物`），git log 就是进度账本。
执行计划的 completed/ 归档与 commit 一一呼应；不拆细碎 PR（2 人极限配置 + 代理协作的节奏）。

## 7. 诚实报告

测试不过说过不过，跳过的验证明说没做。
（本仓库实例：GUI 验证因无浏览器后端未执行，如实记录在案而非宣称通过。）
