# 申报书方案评审 · 2026-09-25

## 范围与方法

- 对象：《巡知项目申报书》（[docs/09](../09-project-application.md)，2026-09-23 版，与提交的 PDF 内容一致）、[docs/08 系统方案](../08-system-solution.md)、当前代码（第三轮修复后）。
- 方法：逐条对照申报书的承诺与代码实现；在空库上用模拟器跑一趟 1234 点巡检，实际生成风险预测和复巡任务，看输出是否支撑申报书的说法；按小麦生长季排时间线。
- 不评：文字润色、经费、人员分工。

## 一、总体结论

1. **写法是强项**：申报书不把预期写成成果，有对照组、有消融、有失败口径（「事件不足只报告流程验证」），还主动引用了主动学习与主动感知的先例并收窄贡献范围。这些正是评委最看重的，建议保持。
2. **最大风险在拿证据，不在写软件**：创新一、二依赖的几样东西——跨日期的观察区域身份、连续的环境记录、图像质量指标、足够数量的发病事件——代码里要么没有，要么是占位值；而小麦病害的观测窗口大约只有 2027 年 3–5 月这一次。
3. **三项创新的实现程度差别很大**：创新三（证据反馈）大部分已实现；创新一、二目前只有接口和启发式占位，拿到真实数据后会退化（实测见第二节）。
4. **有两件事比写代码更急**：播种前在试验田预留小车通道，并定下病种和合作地块（第五节）。

## 二、实测：当前输出能否支撑创新一、二

模拟器 `dry` 场景，12 垄 × 50 m，1234 个采样点（其中 1197 点有照片）：

| 观察项 | 实测结果 | 说明 |
|---|---|---|
| 风险预测的趋势 `trend` | 1197 条全为 `unknown` | 每点只输入 1 次观测。每次巡检都会新建采样点，跨日期无法对上同一个区域 |
| 置信度 `confidence` | 1197 条全为 0.295 | 置信度只由观测次数决定，所有点都一样 |
| 质量分 `quality_score` | 1197 条全为 0.65 | 分析器不产出质量指标，这是缺省值 |
| 生成的复巡任务 | 50 条全为 `revisit` | 质量信号取的是预测置信度（0.295），低于 0.45 的阈值 |
| 任务理由 | 50 条全写「图像质量低于复巡阈值」 | **从未测过图像质量**。这条理由会进入审计记录，和创新三「每条记录可解释」的主张相矛盾 |
| 占位分析器 | 长势 1197 点全为 5 级，NDVI 代理均值 1.0 | 合成图让颜色统计饱和，演示时看不出区别 |

结论：创新二的排序公式本身没问题，但输入它的信号大多是常数，所以输出也分不出高低。只调权重解决不了，必须先补上第三节 P0-1 和 P1-6 两项。

## 三、系统设计问题（按优先级）

### P0：真车采数前必须解决（否则采到的数据不能用于创新一、二的实验）

| # | 问题 | 依据 | 建议 |
|---|---|---|---|
| P0-1 | **没有观察区域身份**。风险预测的 `observation_key` 是 `patrol-{id}/point-{seq}`，每次巡检都不一样；rover 的坐标是从起点按步长推出来的直线，`distance_m` 是 `步长 × 序号` | 申报书 5.1「地块—垄行—观察区段持续身份」；docs/08 §9.3 已经设计了 `observation_key`、`route_chainage_m` | 先实现 v2 协议的最小子集：`observation_key`、`route_chainage_m`、`distance_source`/`position_source`、`client_package_id`。区域按「垄号 + 桩号分段（2–5 m）」划分，不按 0.5 m 的点。用编码器加垄头标记（二维码或反光标）就能稳定关联，不必依赖 RTK |
| P0-2 | **Pi 3B 没有实时时钟**。断网开机时，系统时间可能停在上次关机（fake-hwclock），`captured_at` 会整体偏移，判重、心跳乱序保护、预测窗口都会受影响 | 申报书 7.1 写明现场不依赖公网 | 加一块 DS3231 RTC 模块（十几元），或者让 TX2 用 chrony 做局域网时间源。心跳里上报时钟同步状态；服务端对偏离接收时间过多的时间戳告警 |
| P0-3 | **采集端没有逐点落盘**。整趟照片以 base64 放在内存里，采完才写入队列：中途断电或相机报错，整趟数据全丢。上传是单个 JSON 请求（2600 点 × 每张数十到上百 KB，base64 后约 0.1–0.4 GB），httpx 序列化时还要再复制一份，Pi 3B 只有 1 GB 内存。如果服务端处理时间超过客户端的 120 s 超时，服务端其实已经提交，重传会得到 409，rover 按设计会把包留在队列里等人工处理 | 申报书 7.2「已成功采样即时持久化」「失败采样记录原因」 | 每拍一点就把照片和元数据落盘（JSONL 日志）；拍照失败的点记录原因后继续，不再中止整趟。上传改为两步：先按哈希逐张上传照片（服务端已有的跳过），再提交只含 URL 的元数据包。协议已经支持 `/media/...` URL 引用，只需新增一个照片上传端点。配合 `client_package_id`，第 6 项的 409 死锁也一并解决 |
| P0-4 | **没有连续的环境记录**。天气只有车载的单点快照，rover 的天气字段目前是空的；预报版本也没有存档 | 申报书 7.1「车上单次读数不能替代连续记录」、8.3「保存当时发布的预报版本」 | 布设田间气象站（至少温湿度、降雨、叶面湿润，按小时记录），或接入可追溯的气象数据；每次拉取的预报原样存档。否则 H1 的「天气/生育期基线」这个对照组都建立不起来 |
| P0-5 | **小车能不能下田**。抽穗到灌浆期冠层最高最密，恰好是病害观测的主窗口 | 申报书 7.1「底盘可通过的行距……是试验边界」 | 播种时（约 10 月上中旬）就在试验田预留作业道或加宽部分行距。**错过这次播种就要再等一季** |

### P1：正式实验前

| # | 问题 | 建议 |
|---|---|---|
| P1-6 | 没有图像质量指标（清晰度、曝光、遮挡） | 在分析结果里加入质量字段并升级 `analyzer_version`。复巡排序改用真实质量，不再拿预测置信度当质量；「证据不足」和「图像差」要分成两个信号 |
| P1-7 | 冻结的数据集里没有 train/val/test 划分；模型评估的 `split="test"` 是客户端自己填的字符串，指标也由客户端上报 | 冻结时按地块、日期分组写入划分结果并记录随机种子；评估闸门核对评估集确实来自快照的 test 组；指标尽量由平台根据快照和预测结果重算 |
| P1-8 | 没有从随访结果计算指标的代码；`probability` 是启发式分数，没有校准 | 实现 PR-AUC、Brier、固定误报负担下的召回率和事件级提前量：`intervened` 按删失处理，`unknown`/`insufficient` 不进分母。先在验证集上做校准（Platt 或等渗回归）再报 Brier，否则 Brier 反映的是分数没校准，而不是模型好坏 |
| P1-9 | 没有盲法复核：标注页同时显示模型结论 | 增加盲法模式，隐藏模型输出、选样原因和策略标签（申报书 8.2） |
| P1-10 | TX2 的软件栈：官方最高只到 JetPack 4.6（Ubuntu 18.04 / Python 3.6 / CUDA 10.2 / TensorRT 8.2）；后端要求 Python ≥ 3.12，ultralytics 要求 ≥ 3.8 | 平台跑在 Python 3.12 的 arm64 容器里（不需要 GPU）；推理改用 TensorRT 引擎（YOLO 导出 ONNX 再转 TRT），配一个轻量服务。尽早在 TX2 实机上验证，不要等到联调 |

## 四、三项创新的可行性

| 创新 | 当前实现 | 可行性 | 主要风险 |
|---|---|---|---|
| 一 · 区域连续观察的多源时空风险预测 | 启发式基线 + 接口；缺区域身份、环境历史、质量信号 | **中偏低**，取决于发病事件的数量和区域关联的质量 | 单季、单地块事件太少；俯拍 RGB 看不到下部叶片的早期症状；空间特征需要一致的定位 |
| 二 · 主动复巡与主动学习联动 | 排序与分类的纯函数已有；输入信号大多是常数 | **离线部分高，实车部分中** | 小样本上主动学习的收益常常不稳定；实车对比时病情随时间发展，不同策略不在同一天跑，结果会混进时间因素 |
| 三 · 预警—复核—学习的证据反馈 | 状态机、终态不可改、规则快照、数据集冻结、评估闸门都已实现；本轮补上了窗口口径（D10） | **高** | 评委可能认为这只是「审计日志」 |

### 收敛建议

**创新一**

- 选病种看三条：症状在车载视角能看到；有发病中心并向外扩散（空间特征才有意义）；当地常年发生。条锈病比较契合（先形成发病中心再扩散）。白粉病多从下部叶片开始，俯拍不容易看到。赤霉病受天气驱动强，适合做天气基线，但症状在穗部，年份之间波动大。最终以当地植保站的历年发生资料为准。
- 保证有足够的发病事件：找农科院或农大合作，在病圃或品种区试地上做。多个抗病、感病品种的小区天然形成对照，独立单元也多；必要时人工接种诱发。
- 可证伪的主结论放在「图像 + 历史」相对「仅图像」的增量上；「提前预警」作为次要结论。

**创新二**

- 每次都做全覆盖的基础巡检，策略比较主要用离线重放：在全覆盖数据上模拟各策略会看哪些区域、标哪些样本，天然就是同条件、同预算。实车只用来验证补拍和多视角带来的增量。申报书 9.2 已把离线重放和实车分开报告，建议把离线重放明确为主证据。
- 主动学习要报告多个随机种子下的学习曲线和置信区间，不能只报单次结果。
- 把「主动复巡」收窄为「按桩号定点停车 + 云台多视角补拍」，不做行间自主导航。

**创新三**

- 把价值落到「标签口径会让指标偏多少」上：用自己的数据算一算，如果把没复查的当阴性、窗口没结束就记阴性、处置后没发病也当阴性，PR-AUC 和 Brier 会偏多少。这样的结论可证伪、有数字，比「记录完整率」更有说服力。前两条口径本轮已在系统里强制执行（D10）。
