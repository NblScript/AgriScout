# AgriScout 系统蓝图（草案 v0.3）

> 状态：已整合全部参考资料精读结果（2 案例 + 3 论文），待确认 MVP 范围后进入开发

## 一句话定位
田间巡检小车每 0.5 米拍照 + 采集天气数据 → 平台自动判断作物生长情况 → 给出农事建议的农作物全生命周期管理系统。

## 目标用户
农业企业 / 农业技术员：管理多个地块、巡检任务、对比分析、导出报告。

## 技术选型（已确认）
- 形态：Web 平台（浏览器访问，地图 + 图表）
- 后端：Python（FastAPI）
- 前端：Vue 3
- AI：流程先行，识别接口预留，后接 YOLO 等模型
- 数据库：PostgreSQL（含空间数据 PostGIS，用于轨迹/采样点）

## 总体架构（v0.2：端-边-云三层，依据 Sensors 25(17):5302 与 Frontiers 16:1668545）

```
┌────────────── 端（Device：巡田小车）──────────────┐
│ 行走控制 + 每0.5m触发拍照(RGB) + 天气传感器        │
│ + 主动光源NDVI/RVI光谱传感器(长势) + RTK/GPS/IMU   │
│ + 边缘板(可选RK3588)：压缩/特征提取，能耗仅8–15%   │
│ → 小数据走 LoRa/LoRaWAN，图像走 4G/5G，离线缓存    │
└───────────────────────┬──────────────────────────┘
                        ▼ (MQTT/HTTP，弱网由边缘轻量模型兜底)
┌────────────── 边（Edge：田间网关/车载计算机）──────┐
│ 实时推理（轻量YOLO）、实时决策、增量学习、离线兜底   │
│ "边缘执行→云演进"：边缘筛选高风险样本上传云端       │
└───────────────────────┬──────────────────────────┘
                        ▼
┌────────────── 云（Cloud：Web 平台）────────────────┐
│ ① 数据接入 API（图像/天气/定位/地块元数据，MQTT）    │
│ ② 图像分析引擎（接口抽象，占位→真实模型可替换）      │
│ ③ 生长评估（阶段+长势NDVI+病虫害风险评分）           │
│ ④ 建议引擎（规则库：作物×阶段×天气阈值→农事建议）    │
│ ⑤ 展示层（地块地图/轨迹/采样点热力/时间轴/报表）     │
│ ⑥ 标注数据回流：照片→人工复核→扩充垂直数据集        │
│ 演进预留：数字孪生 / 联邦学习 / LLM 农事报告         │
└───────────────────────────────────────────────────┘
```

## 小车硬件参考（依据 Agronomy 13(12):3043 + 火眼金睛案例）

| 项 | 参考规格 | 来源 |
|----|----------|------|
| 底盘 | 轮式四驱、离地 85–145cm 可调、轮距可调、窄轮 7cm（不压苗） | 南农论文 |
| 动力 | 轮毂电机 480W/48V×4、60V/20Ah 续航约 3h、载荷约 15kg | 南农论文 |
| 车速 | 0.1–0.3 m/s（每 0.5m 一个点 = 1.7–5s/点，节拍匹配） | 南农论文 |
| 长势传感 | 主动光源 730/810nm 双波段 NDVI/RVI（底盘下、距冠层 40–60cm） | 南农论文 |
| 视觉 | RGB 高清相机 + 可选激光雷达 + RTK + IMU | 火眼金睛 |
| 边缘算力 | RK3588 + 轻量化 YOLO（YOLOv8Ghost 参考：7.7ms/张、86.73%） | 火眼金睛 |
| 通信 | LoRa 传天气/状态小数据 + 4G/5G 传图像，离线缓存 | Frontiers 综述 |

## 核心数据模型（v0.1）

| 实体 | 说明 |
|------|------|
| User | 技术员/管理员，角色权限 |
| Field | 地块：边界多边形、面积、土壤类型 |
| Crop | 作物：品种、生命周期参数（播种~收获、阶段划分） |
| Planting | 种植记录：地块×作物×批次×时间 |
| Patrol | 巡检任务：小车、地块、轨迹、时间段 |
| CapturePoint | 采样点（每0.5m一个）：照片、坐标、天气快照 |
| WeatherSample | 天气时序数据：温湿度/光照/风速/降水 |
| Analysis | 采样点分析结果：生长阶段概率、长势等级、病虫害风险 |
| Advice | 农事建议：内容、来源规则、采纳状态 |

## 分期路线

| 阶段 | 内容 | 交付物 |
|------|------|--------|
| P0 骨架 | 脚手架 + 数据模型 + 地块/作物管理 + 上传 API | 能存数据、看地块列表 |
| P1 链路闭环 | 模拟数据生成器 → 上传 → 占位识别 → 评估 → 建议 | 假数据跑通"拍照→判断→建议" |
| P2 可视化 | 地块地图 + 轨迹 + 采样点热力图 + 时间轴回放 | 技术员直观巡看全场 |
| P3 真实接入 | 真实图像模型 / 小车通信协议 / 真实传感器 | 真车上场 |
| P4 深化 | 全生命周期档案、产量预测、多季对比、预警推送 | 完整系统 |

## 参考资料关键结论（v0.3 整合全部精读结果）

| 结论 | 来源 | 对 AgriScout 的含义 |
|------|------|---------------------|
| RK3588 + 轻量化 YOLO（YOLOv8Ghost）端侧推理 7.7ms/张、86.73% 准确率可行 | 火眼金睛特种车 | 小车端侧推理是成熟方案，MVP 云端占位算法 + 接口预留即可，后续可下沉到边缘 |
| 视觉 + RTK/激光雷达空间绑定，报告含"类型/严重程度/位置" | 火眼金睛特种车 | 每 0.5m 采样点必须带坐标，Analysis 报告要含位置字段 |
| 自建垂直标注数据库是识别质量关键（柠檬病虫害库） | 火眼金睛特种车 | 平台要设计"标注数据回流"闭环：采集照片→人工复核→扩充数据集 |
| 识别→诊断→决策闭环，农户手机实时看数据 | 神农卫田 | 建议引擎（作物×阶段×天气→农事）是核心差异化，不是附加功能 |
| 多装置分工（巡检/精准识别/诱捕监测）而非一台设备包打天下 | 神农卫田 | 系统要把"采集载体"抽象化：小车、无人机、固定监测点都只是数据源 |
| 覆盖 75 种作物 615 种病虫害需要大模型支撑 | 神农卫田 | MVP 先聚焦少数作物+病虫害，数据库按品种×阶段扩展 |
| 端=预处理(能耗8–15%)、边=实时推理+增量学习、云=跨生育期建模（"边缘执行-云演进"） | Sensors 25(17):5302 | 三层职责划分直接采纳；弱网离线兜底是农田刚需 |
| 高离地(85–145cm)可调轮距窄轮 + 0.1–0.3m/s 车速 | Agronomy 13(12):3043 | 不压苗 + 车速与 0.5m 采样节拍匹配，作为小车选型硬指标 |
| 主动光源 730/810nm NDVI/RVI 光谱传感器定量长势(LAI/生物量/氮) | Agronomy 13(12):3043 | 长势评估用光谱+RGB 双通道，比纯 RGB 可靠、不受光照影响 |
| LoRa 传小数据 + 4G/5G 传图像；MQTT 互操作 | Frontiers 16:1668545 | 通信方案：天气/状态走 LoRa，图像走蜂窝网，接入层用 MQTT |
| 边缘 YOLO 筛高风险样本 + 云时空预测；数字孪生/联邦学习/LLM 报告是演进方向 | Frontiers 16:1668545 | 平台演进预留位；建议引擎后期可升级 LLM 农事报告 |
