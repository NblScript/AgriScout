# 巡知项目申报书

## ——以主动学习驱动复巡，以时空证据预测病害风险

> 建议申报名称：**巡知——面向病害风险预测与主动学习的农田智能巡检系统**
>
> 申报用途：面向挑战杯的技术申报正文底稿。本文描述建设目标、拟研究方法和验证方案，不列开发进度，不将预期效果写成实测成果。
>
> 研究范围：以小麦为首批作物，在试验地选择一种有连续观测和专家判读条件的病害开展验证；病虫害综合管理为扩展方向。
>
> 编写日期：2026年9月23日

## 一、项目摘要

“巡知”面向小地块、试验田和合作社的作物健康管理需求，拟研制一套能够持续观察、预测风险、主动复巡和积累农业知识的智能巡检系统。项目以四驱小车、摄像头和二自由度云台为近地感知载体，以 Raspberry Pi 3B 和 Jetson TX2 实现采集与边缘分析，通过农田管理平台贯通图像记录、环境观测、风险预测、专家复核和模型更新。

项目重点研究三个问题：一是如何利用同一区域的连续观察，提高病害风险判断的针对性；二是如何在有限续航和人工标注时间下，选择更值得复查的区域和更值得标注的样本；三是如何将预警、复核和后续结果对应起来，持续发现误报、漏报及其原因。

围绕这些问题，项目拟形成三项相互关联的创新：构建面向固定观察区域的多源时空风险预测方法；构建兼顾病害风险、信息价值和作业成本的主动复巡与主动学习联动机制；构建贯穿预警、复核、处置记录和后续观察的证据反馈机制。系统输出具体区域的风险等级、预测时间窗、依据和复查任务，由农技人员确认关键结论。

项目以相同巡检时间、相同标注预算和独立测试地块为比较条件，检验新增时序信息是否改善预测、主动复巡是否提升有效发现、主动学习是否降低达到同等性能所需的标注成本。最终交付巡检装备、场边计算服务、管理平台、数据规范、模型及可复现实验材料，为农田精细化管理提供一种可持续积累证据的技术路径。

## 二、立项依据与需要解决的问题

### 2.1 观察不足：知道地块有风险，却难以确定应先检查哪里

小地块管理需要把“全田概况”转化为“具体区域需要什么检查”。项目关注的实际困难包括：人工逐点巡查耗时，观察记录难以保持一致；密集植株会形成遮挡；宏观图像与近距离叶片证据之间存在尺度差异。巡检任务若始终采用相同路线和频率，就会在低变化区域重复采集，却可能缺少对疑点的进一步观察。

本项目据此提出“基础覆盖巡检＋疑点定向复巡”：先建立覆盖记录，再根据风险与信息缺口选择区域补拍，并保留少量随机抽查以发现系统尚未识别的异常。目标是提高单位巡检时间获得的有效证据，而非一味增加照片数量。

### 2.2 判断不足：一次识别无法说明未来变化

一张图像能够提供某个时刻的可见线索，但发生风险还与历史变化、病害类型、生育期和环境过程有关。例如，De Wolf 等针对小麦赤霉病的研究已利用花期附近的天气信息建立风险模型，说明病害预测需要明确作物阶段和时间条件。[研究原文](https://www.apsnet.org/publications/phytopathology/2003/April/Pages/93_4_428.aspx)

项目将预测目标落实到“哪个观察区域、在多长时间内、出现哪种可核查事件”，融合近地观察与环境历史，帮助农技人员确定复查顺序。无明显可见症状时，输出是基于条件和历史证据的风险判断；不能据此声称 RGB 摄像头能够直接识别尚无可见症状的感染。

### 2.3 学习成本高：照片积累不等于有效知识积累

农业图像会随地块、品种、季节和采集条件变化。Mohanty 等的植物病害识别研究报告了训练条件与外部图像条件不一致时的性能下降，提示模型需要在实际应用条件下检验。[研究原文](https://arxiv.org/abs/1604.03169)

项目要解决的具体问题是：同一条垄行的大量相似照片不应消耗重复标注时间，低质量图像不应仅因模型“拿不准”就进入高优先级标注队列，罕见且有代表性的样本又不能被忽略。系统因此需要同时管理图像质量、样本多样性、专家时间和训练收益。

### 2.4 反馈不足：预警发出了，后续是否正确却难以追踪

一次风险提醒只有和后续核查对应起来，才能判断其价值。若历史模型结果被新结果覆盖，若“没有复查”被当作“没有发病”，或若处理措施没有记录，系统就无法可靠解释误报和漏报。

项目将每次预警与原图、观察区域、预测窗口、模型版本和人工结论绑定，区分“确认阳性、确认阴性、待核查、证据不足、受处置影响”等状态。该机制服务于现场复查，也为预测验证和模型改进提供可靠标签。

## 三、研究定位与已有方案的关系

病害识别、风险预测、主动学习和机器人主动感知均有已有研究基础。项目的研究贡献应落在面向本项目场景的具体方法、约束与实验结果上。

| 已有研究或方法 | 已有能力 | 本项目拟研究的具体贡献 |
|---|---|---|
| 单图植物病害识别 | 从图像识别可见症状；应用条件变化可能影响效果 | 把图像关联为区域级时间序列，并让质量和缺失信息参与风险判断 |
| 天气驱动的小麦病害风险模型 | 利用环境和生育期信息估计发生风险 | 检验近地视觉历史是否能为小区域风险增加有效信息 |
| 不确定性驱动的主动学习 | 选择有价值的样本交由人工标注 | 同时考虑复巡成本、标注时间、重复样本和区域代表性 |
| 病害主动感知机器人 | 根据置信度选择更有价值的观察视角 | 在行间移动与二自由度云台约束下，联动跨日期复巡和训练样本选择 |
| 规则建议和管理平台 | 支持记录、查询、规则匹配和结果展示 | 建立预警到后续核查的证据对应，用于识别并处理反馈偏差 |

主动学习的基本思想已有系统研究，不能把“挑选不确定样本”本身作为原创算法声明。[Settles 技术报告](https://minds.wisconsin.edu/handle/1793/60660)

CMU 的苹果树病害研究已将置信度地图与下一观察视角规划结合，说明“让机器人主动寻找更有价值的视角”也存在直接先例。该研究使用的果树场景与相机操作结构不同于本项目，但构成需要认真对照的相关工作。[CMU 原始研究](https://publications.ri.cmu.edu/robotic-localization-and-mapping-of-disease-in-apple-orchards)

基于这些资料，本项目将差异化研究定位为：**面向小麦行间巡检，在有限运动能力、算力、续航和专家时间下，把区域风险预测、主动复巡与主动学习组织为同一套可比较的决策流程。**这一定位是项目研究假设，实际优势通过对照实验确认。

## 四、项目目标与总体技术路线

### 4.1 最终目标

研制一套支持“采集—分析—预警—复核—再采集—再学习”的农田巡检系统，使用户可以：

1. 查看地块中哪些区域已经观察、哪些区域存在遮挡或证据缺失。
2. 查看目标病害在指定未来时间窗内的区域风险及主要依据。
3. 获取有位置范围、观察目标、优先级和完成时限的复巡任务。
4. 对高价值样本进行复核，记录不确定或无法判断的情况。
5. 回看预警是否被后续观测证实，并追踪模型更新带来的变化。

### 4.2 技术路线

```text
地块、作物和观察区域建档
        ↓
基础覆盖巡检 → 质量检查 → 近地照片与环境历史
        ↓
区域关联 → 单次检测 → 多源时空风险预测
        ↓
风险、信息价值与作业成本联合排序
        ├─ 需要新证据 → 定向复巡/调整视角 → 补充采集
        ├─ 图像可用但类别存疑 → 专家标注 → 数据集版本
        └─ 证据充分 → 复查建议 → 人工确认与后续核查
                                               ↓
                           独立评估 → 批准模型更新
```

### 4.3 作物与任务边界

以小麦为首批作物，选择当地具有发生机会、连续观察条件和专家判读条件的一种病害作为验证对象。多作物、多病害和虫情扩展分别建立采集条件、标签和评估方法，不将一个病害的结果直接推广到其他病虫害。

对于可见虫体或虫害症状，可探索近距离图像识别；对于需要虫口密度或飞行虫情数据的任务，再按对象配置诱捕或专用传感装置。是否扩展取决于目标任务的观测条件。

## 五、三项重点创新及其实际价值

### 5.1 创新一：以区域连续观察为基础的多源时空风险预测

**拟解决的问题。** 单次识别缺乏变化过程，环境风险缺乏现场局部证据，两者都可能难以支持精确的复查安排。

**技术机制。** 系统以“地块—垄行—观察区段”建立持续身份，在每次巡检中记录图像、拍摄视角、区域定位误差、图像质量和环境数据来源。视角和定位不满足关联条件时，保留为区域级观测，避免误认为同一株或同一片叶。

在此基础上构建视觉、时间、空间、环境四组特征：

| 信息 | 主要内容 | 对预测的作用 |
|---|---|---|
| 视觉 | 可见异常比例、病斑候选、叶色与覆盖变化 | 描述观察时点的证据 |
| 时间 | 多次观测的变化幅度、持续性、缺测间隔 | 区分持续发展与偶然波动 |
| 空间 | 邻近区域的异常密度、风险变化 | 提供空间聚集线索，不直接等同于因果传播 |
| 环境与作物 | 观测时点以前的温湿度、降雨、叶面湿润条件、生育期和品种 | 补充与目标病害相关的发生条件 |

图像质量、定位误差和环境缺测作为单独输入或可靠性门控。证据不足时降低结论置信度，并生成补采任务。建模从可解释的逻辑回归或树模型开始，在同样数据划分下检验增加时序结构的必要性。

**拟形成的差异。** 将环境驱动的风险判断与本地小区域的连续视觉证据连接，并显式处理复访误差、图像不可比和数据缺失。

**实际价值。** 帮助农技人员把“近期天气可能有风险”进一步落到“哪些区段需要优先检查”，并区分异常正在增加、稳定存在或证据不足。是否产生提前预警效果，以前瞻观测检验。

**验证方式。** 在统一预测目标下比较天气与生育期基线、仅用观察时点图像的基线、图像加历史基线、完整多源模型；分别去掉历史、环境、空间和质量信息，检验各组信息的增量价值。

### 5.2 创新二：将主动学习与机器人复巡联动的预算分配方法

**拟解决的问题。** 只选择低置信度图片可能反复选择模糊、遮挡或重复内容；只进行人工标注不能获得缺失视角；只沿固定路线巡检又不能灵活补充关键证据。

**技术机制。** 将“补拍什么”和“标注什么”作为两个相关决策：

- **主动感知/复巡**：决定去哪里、何时去、用什么角度补充观测。
- **主动学习**：决定哪些可用样本应交由专家标注，用于改善模型。

系统先做质量检查和去重，再综合区域风险、模型不确定性、历史变化、样本代表性及任务成本生成候选任务。优先级可用以下可解释形式作为研究起点：

```text
任务价值 = 风险关注度 + 预期信息收益 + 样本代表性 - 重复惩罚 - 作业成本
约束：巡检时间、剩余电量、路线可达性、专家标注时间
```

各项经过归一化，权重在训练或验证数据上确定并固定，最终测试集不参与调参。作业成本分别记录移动、补拍和标注时间，不能只用照片数量代替成本。

对模糊图像优先重新拍摄；对清晰但类别冲突的图像优先人工复核；对变化快且风险高的区域优先提前复巡；对高质量、高置信但陌生场景的样本保留代表性抽查。每轮还保留基础覆盖与随机抽查任务，防止持续忽略模型自信但判断错误的区域。

**拟形成的差异。** 在同一预算中协调风险复查、视角补充和样本标注，使“重新看一次”与“请专家判一次”具有不同的触发条件。研究贡献定位于这一场景下的联动方法与实证，不将主动感知或主动学习的基本思想作为本项目首创。

**实际价值。** 减少重复拍摄和低效标注，将有限人力与续航优先用于可能改变判断的任务，并为模型提供具有本地代表性的样本。

**验证方式。** 分别比较固定路线与主动复巡、随机标注与单纯不确定性标注与联合策略。使用相同的初始模型、相同数据候选池和相同预算，报告独立测试集性能、实际标注分钟数、巡检时间和疑点确认效率。

### 5.3 创新三：贯穿预警、复核和学习的证据反馈机制

**拟解决的问题。** 提醒缺乏证据、后续核查与原预警脱节，会使用户难以信任结论，也使模型无法获得可信的改进信号。

**技术机制。** 每条风险记录绑定观察区域、预测时点、时间窗、原始数据、模型版本和主要依据；复巡任务和人工结论沿用这一关联。系统将“病害类别复核”和“未来风险是否兑现”分别记录，避免把一张病斑图的标注误当成未来事件标签。

建议以规则约束生成，保存命中条件与规则快照。人工可选择确认、驳回、待观察或证据不足。处置时间与措施单独记录，后续未发病若发生在处理之后，不能直接判定早先预测错误。模型重新分析或规则更新不覆盖历史结果。

**拟形成的差异。** 把审计记录用于构建可靠标签、识别反馈偏差和安排下一轮核查，而不仅是查询历史报告。该项属于支撑前两项研究的系统机制创新，其价值需要通过核查效率和标签一致性检验。

**实际价值。** 用户可以回答“为什么提醒、有没有复查、后来怎样”；研发人员可以区分图像误识别、预测失准、观测缺失与处置影响，减少错误标签进入训练集。

**验证方式。** 对预警记录进行从原图到后续事件的完整回放；由独立复核人员核查证据；比较有无完整关联时的核查用时、结论一致性和标签缺失率。

## 六、创新与现实问题的对应关系

| 现实问题 | 对应机制 | 用户得到的结果 | 成效证据 |
|---|---|---|---|
| 不知道该先检查哪里 | 时空风险预测与风险分级 | 带区域和时间窗的复查清单 | 相同误报负担下的事件召回率、预警提前量 |
| 反复采集相似照片 | 去重、代表性约束和主动复巡 | 更少无效补拍，更多有效视角 | 单位巡检时间确认的独立疑点数 |
| 专家标注时间不足 | 质量门控与主动学习 | 有优先级的少量复核任务 | 达到同等性能所需的标注分钟数 |
| 模型不适应新地块 | 本地样本回流与独立评估 | 有证据支持的模型更新 | 留出地块或后续日期上的性能变化 |
| 提醒缺依据、结果难追踪 | 预警与复查的证据关联 | 可回看、可解释的风险记录 | 记录完整率、核查用时和一致性 |

以上为待验证的目标收益。硬件数量、平台页面数量和照片总量不作为创新效果的替代指标。

## 七、硬件与软件实现方案

### 7.1 硬件分工

| 设备 | 分工 |
|---|---|
| Raspberry Pi 3B | 车端任务编排、图像采集、状态读取、持久化队列与 HTTP 通信 |
| PWR-A53 驱动板、四驱底盘 | 按适配接口完成低速移动、减速与停车 |
| Robot-Eye 摄像头、二自由度云台 | 在可达视角范围内采集冠层、侧面和局部疑点 |
| 超声波和红外避障模块 | 提供障碍信息，参与减速、停车与人工接管 |
| 8.4V 锂电池 | 经匹配的保护和稳压电路为车端供电 |
| Jetson TX2 | 场边图像推理及轻量平台服务，使用独立适配电源 |

默认 Pi 3B 在车上，TX2 作为场边主机，通过局域网通信；手机或浏览器用于操作。目标现场部署不依赖额外 PC，远程服务器用于扩展部署，训练资源与现场推理环境分离。

为形成可靠的区域关联，设计中补充编码器以及标记物或适用定位方式，并记录定位来源与误差。环境历史由连续采集装置或可追溯气象数据源提供；车上单次温湿度读数不能替代连续环境记录。图像采样密度通过试验确定，0.5 米等间距仅作为候选参数，不预先承诺精度。

车端软件执行任务和软监控，实体急停、电机使能与失联看门狗由硬件链路保障；普通 Linux 调度不承担确定时限的安全停车保证。底盘可通过的行距、地面条件和生育期是试验边界，云台转动不能保证看清所有被遮挡部位。

### 7.2 软件组成

- **采集端**：任务执行、相机与云台控制、传感适配、已成功采样即时持久化、断网队列和状态上报。
- **边缘端**：图像质量评估、轻量模型推理、疑点摘要和模型版本管理。
- **平台端**：地块与观察区域管理、异步分析、时序特征、风险预测、复巡调度、规则建议及人工复核。
- **训练端**：数据集冻结、标注审查、模型训练、独立评估和发布审批。
- **用户界面**：地图、时间轴、风险清单、原图证据、待复核任务和模型效果对比。

采集端通过公开数据合同接入，不导入后端内部模块。照片独立存储，数据库保存引用与元数据。上传与分析解耦，避免计算堵塞采集；成功采集的照片及时落盘，失败采样记录原因，不能将拍摄失败当成可恢复的有效照片。

## 八、预测任务与数据标签设计

### 8.1 定义预测时点、区域和事件

将风险输出定义为：

```text
R(g, t, H) = 在时点 t 已获得的信息下，
             观察区域 g 在未来窗口 H 内发生目标事件的概率
```

首次显症和病情加重作为两个独立任务：

- **首次显症**：区域在时点 t 经规定流程检查未发现目标症状，在窗口 H 内由独立复查首次确认。这里的“首次”是首次被规定观察流程发现，不推断生物学感染起点。
- **病情加重**：区域在时点 t 已有目标病害，窗口结束前的病情指标相对基线达到预先规定的增幅。

预测时间窗 H、病情尺度、增幅阈值和复查节律，依据选定病种和试验条件在测试开始前确定。48 小时可以作为候选窗口之一，不能在病种未确定前作为通用承诺。不同病害的潜伏期并不一致，这一边界也符合农艺资料对潜伏期差异的说明。[AHDB 病害管理资料](https://ahdb.org.uk/knowledge-library/introduction-to-foliar-disease-management-in-cereals)

### 8.2 建立可核查标签

对所有进入预测试验的区域执行统一的后续核查流程，阳性由合格复核人员确认，疑难样本转交植保专家进一步鉴别。阴性需要完成规定窗口的复查；失访、遮挡、严重图像质量问题或未完成观察标记为未知，不能作为健康标签。

独立测试集的标签复核采用盲法，界面隐藏模型预测、选样原因和策略标签，分歧通过二次判读解决。为估计漏报，预先设置固定参考区域和随机抽查区域，低风险区域也接受核查，不能只验证系统推荐的高风险点。

### 8.3 防止信息泄漏与反馈偏差

预测输入只使用时点 t 及以前的信息。若使用天气预报，保存当时实际发布的预报版本，不能用事后实测天气代替当时可用信息。

数据划分按地块和时间分组，重复图像、邻近帧与同一事件不能同时进入训练和测试；跨划分边界的重叠时间窗需要隔离。标准化、阈值设定和参数选择仅使用训练、验证数据。

训练用的主动选样与独立评估集分开管理。记录人工复巡和施药等干预；受干预影响的随访采用单独分层或删失处理，不要求农户为试验延误必要防治。未经进一步实验，预测准确率提升不能直接解释为减药或增产。

## 九、实验与验收方案

### 9.1 研究假设

- **H1**：连续近地视觉与环境信息的组合，相比单一信息源能改善指定窗口内的区域风险预测。
- **H2**：在相同巡检预算下，联合策略比固定巡检或仅按风险巡检获得更多有助于确认疑点的证据。
- **H3**：在相同标注预算下，质量、代表性与不确定性联合选择比随机或单纯不确定性选择更有利于独立测试集表现。
- **H4**：预警与随访证据关联可减少标签缺失，提升人工核查效率。

### 9.2 对照与指标

| 实验 | 对照设计 | 主要指标 |
|---|---|---|
| 风险预测 | 天气/生育期、仅图像、图像加历史、完整模型；对齐相同未来事件 | PR-AUC、Brier 分数、固定误报负担下的召回率 |
| 提前预警 | 统一独立核查节律下的首次确认，与模型首次有效预警比较 | 事件级提前量、未预警事件比例、每地块日误报数 |
| 主动复巡 | 固定路线、风险优先、风险与信息价值联合策略 | 单位时间独立疑点确认数、漏查率、总路程与电量 |
| 主动学习 | 相同初始模型与候选池，比较随机、仅不确定性、联合策略 | 学习曲线、达到同等效果的标注时间、类别覆盖 |
| 采样策略 | 不同间距、视角和复访间隔 | 病害区域发现率、图像可用率、任务用时 |
| 证据反馈 | 有无结构化关联的人工核查任务 | 核查用时、判读一致性、标签缺失率 |
| 可靠性 | 断网、超时、非 JSON 响应、重启、相机异常 | 已落盘数据完整性、重复上传幂等性、部分任务恢复 |
| 运行安全 | 急停、通信失联、障碍、低电压 | 停车响应与故障状态，边界内重复试验结果 |

PR-AUC 用于观察类别不平衡下的预测表现，Brier 分数用于评估概率与实际结果的一致程度。预警提前量应同时报告未被预警的事件，不能只选择成功案例求平均；未来事件仅在两次核查之间发生时，按区间表达时间不确定性。

离线重放用于比较策略逻辑，实车实验用于比较路线、耗时和补拍效果，两类证据分别报告。重复拍到同一病斑不重复计作有效发现。

### 9.3 试验组织与通过标准

试验分为基线采集、方案固定和独立评估三个环节。基线用于估计发病事件数量、数据质量和所需样本规模；方案固定时登记病种、H、阈值、预算、主指标与最小实用改进幅度；独立评估阶段不得再依据测试结果改动这些设定。

结果按地块或独立病害事件统计，并报告样本量、置信区间及失败情形。若缺少足够发病事件，只能报告采集与技术流程验证，不能据此宣布预测有效。各创新是否成立由对应对照结论决定，不以单张检测图或一次演示代替。

## 十、应用价值与推广路径

### 10.1 农业生产价值

系统将风险判断转化为带区域、理由和时限的复查任务，帮助农技人员分配巡检时间。反复观测形成可以比较的病情记录，便于后续分析管理措施与观察结果的关系。

投入产出按单亩巡检时间、专家复核时间、装备维护、供电和数据成本核算；减药、增产和防治成本收益需要专门田间对照才能形成结论。低成本是设计目标，采购与维护费用以实际清单记录。

### 10.2 科研与教学价值

项目形成带有空间、时间、质量、复核和处置信息的观测数据，为病害预测、主动感知和主动学习提供可复现载体。教学或育种试验可按小区重复观察，输出明确来源的对照材料。

### 10.3 推广路径

从具备行间通行条件的小麦试验田开展验证，再向作物结构相近、管理需求明确的家庭农场和合作社试点扩展。进入新地块前重新检查通行条件、采集视角和模型表现；通过统一接口逐步接入其他设备或气象数据。

## 十二、可直接用于申报表的精简正文

### 12.1 项目简介

巡知是一套面向小麦等作物病害风险预测与主动学习的智能巡检系统。项目以移动小车进行近地采样，以 Raspberry Pi 3B 完成车端采集与通信，以 Jetson TX2 承担场边分析和轻量平台服务，形成“巡检—预测—复核—复巡—学习”的连续流程。

项目拟解决三类问题：单次观察难以判断后续风险，固定巡检和全量标注消耗有限资源，预警与后续结果脱节导致知识难以积累。为此，项目以固定观察区域组织多日期图像，融合病害线索、环境历史、生育期和数据质量形成区域风险预测；再结合风险、信息价值、代表性及作业成本，选择需要补拍的区域与需要专家判读的样本；通过可追溯记录把预警、复查、处置与后续观察关联，形成可靠训练数据。

项目以一种目标病害开展前瞻验证，按相同巡检和标注预算比较不同策略，并在独立地块或后续日期检验预测效果。预期形成可复用的巡检装备、决策平台和实验方法，为农业管理提供有证据、有重点、能持续改进的观察与复查工具。

### 12.2 创新性与拟解决问题

一是研究区域连续观察驱动的多源风险预测。针对单次图像缺乏变化过程、环境风险缺少局部现场证据的问题，将同一区域的多日期图像与生育期、环境历史共同建模，并处理定位误差、图像质量与缺失信息，输出具有时间窗和证据依据的风险结果。

二是研究主动复巡与主动学习的联动方法。针对小车续航和专家时间有限的问题，把补拍、复巡和标注区分为不同任务，综合风险、不确定性、样本代表性及执行成本排序，在基础覆盖和随机抽查保障下优先获得有价值的信息。

三是建立预警到后续核查的证据反馈机制。针对结论难复核、误报漏报原因不清和训练标签容易失真的问题，关联原始数据、模型版本、人工判断、处置记录与随访结果，使反馈能够用于核查现场问题和检验模型效果。

三项研究共同服务于一个目标：用有限的巡检和人工投入，获得更有助于判断病害风险的证据，并通过可验证反馈持续改进系统。端边协同、断网续传和管理界面为这一目标提供工程支撑。

### 12.3 实际应用价值

系统面向农技人员和地块管理者，提供可定位的风险清单、可解释的复查理由和可回看的变化记录。预期价值体现在减少重复巡查、提高疑点确认效率、降低无效标注投入和改善风险判断的一致性。相关效益通过巡检用时、标注时间、独立测试集表现及证据核查结果量化，不以未经验证的增产或减药比例代替实证。
