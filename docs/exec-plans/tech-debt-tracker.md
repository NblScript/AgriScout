## 复盘：地图 403 事件时间线（2026-08-27~28，五代方案）

| 版本 | 方案 | 死因 |
|---|---|---|
| MV1-4 | OSM 本地缓存 + 浏览器端在线回退 | ① 批量下载触发 OSM 反滥用封锁（IP 级，连坐浏览器）；② 回退机制写错（onTileError 是 OpenLayers 接口，Leaflet 不调用）；③ CARTO 改政策无 key 返回错误占位图 |
| MV5-6 | 砍在线回退 + 换路径 /maptiles | 方向正确但两个盲区：缓存半径 1.2km 小于视口（边缘 404 灰块）；旧 URL 的浏览器缓存毒条目仍在 |
| MV7 | minZoom 13 + 日志陷阱 | 服务端日志全量记录 107 个 404，定位「缩小地图越出缓存下限」——铁证方法论确立 |
| **MV8** | **高德本地瓦片（终案）** | 新 URL 空间 + 新上游 + GCJ-02 换算，前三代的失败因子全部规避 |

**方法论教训**（已体现于 core-beliefs.md §7）：
1. 「显示异常」先上服务端日志抓真实请求，不靠用户截图猜——截图猜错两轮，日志一上立破案
2. 浏览器磁盘缓存按 URL 键存取：URL 不变，服务端怎么修都无效；换路径是最便宜的解毒剂
3. 第三方免费瓦片源都不可作为演示依赖（封锁/政策/key 三种死法），唯一可靠源是自己预缓存的本地瓦片
4. 验证页（map-check.html）+ 版本徽标（MV{n}）是排查浏览器侧问题的利器：隔离变量 + 一眼识别实际运行代码
