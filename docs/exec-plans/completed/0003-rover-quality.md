# 0003 · 真车采集端代码质量改造

## 状态
已完成（2026-09-14）

## 背景
PR #1 新增了 `rover/` 真车采集端，但采集、硬件资源、建档、协议组装和上传逻辑集中在一个入口函数中，异常处理和资源释放边界不足，也缺少针对采集端的可执行验证。目标是在不改变巡检包协议和 HTTP 隔离红线的前提下，拆出清晰的职责边界，提升失败可诊断性与测试性。

## 决策记录
- 保留 `rover/` 只通过 HTTP 调用平台，不复用后端内部模块。
- 保留 `--fake` 链路作为无硬件验收入口；真实摄像头实现必须显式释放资源。
- 采集失败时不上传不完整巡检包，上传失败返回非零退出码并关闭客户端。

## 进度
- [x] 获取 PR 分支并建立本地改造分支
- [x] 拆分采集端职责并补充边界校验
- [x] 增加可执行的静态验证（py_compile、diff check）
- [x] 完成文档与计划收尾

## 最终结果
`rover/run.py` 已拆分为 HTTP 客户端、采集源、建档、点位采集和巡检包组装职责；补充参数校验、实际采集时间、单点结束时间、网络/JSON 错误转换和异常路径资源释放。新增 `rover/test_run_smoke.py`，用本地 HTTP mock 验证 `--fake` 上传、时间顺序、错误归一化和采集失败清理；真实摄像头仍需硬件现场验证。
