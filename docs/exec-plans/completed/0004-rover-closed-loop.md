# 0004 · Rover 车端采集闭环

## 状态
已完成，2026-09-19

## 背景
现有 `rover/run.py` 已能通过巡检包 HTTP 协议完成一次采集和上传，并有无硬件烟测，但采集点的距离、坐标和天气仍是占位值，采集包只在内存中保存。弱网络或进程退出会造成照片和采集记录丢失，后续也无法可靠支撑跨日区域复访、风险预测和主动学习。

方案取舍：车端先实现协议兼容的本地持久队列、安全重传和可替换的采集元数据源；不在本次改动中虚构编码器、GPS、天气传感器或边缘模型，也不修改后端巡检包协议。这样可以在无硬件环境用 fake 和本地 HTTP mock 验证故障恢复，再逐步接入真实传感器。

## 决策记录
- 队列以每个完整巡检包一个 JSON 文件保存，采用临时文件加原子替换，照片仍遵循现有 base64/URL 协议。
- 上传成功后删除队列文件；网络、非 JSON、HTTP 错误保留队列文件。当前后端没有 client package id，409 只记录为待核对，不自动删除队列文件。
- 首次实现提供 `--flush-spool`，不启动新的采集任务，只补传本地队列；后续可由 Pi 的定时任务或现场脚本触发。
- 车端仍只依赖 HTTP 协议，不导入 backend 内部模块。
