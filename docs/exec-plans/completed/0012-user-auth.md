# 0012 · 用户登录与角色权限：填上认证插槽（B4）

## 状态
已完成（2026-09-29）。方向讨论期间先做的、与方向无关的平台能力。

## 背景
基线 B4 砍掉了登录，所有接口经 `get_current_user` 插槽放行。技术债台账把「无用户认证」列为答辩必答项：评委会问谁能看、谁能改、
复核结论是谁下的；平台也不能在接口全开放的状态下放到公网演示。插槽设计的初衷就是「以后只换实现、业务接口零改」，本计划兑现它。

取舍：
- **令牌方案**：JWT（HS256）无状态，前端、模拟器、小车统一用 `Authorization: Bearer`。后端没有 PyJWT/bcrypt，
  且本机 venv 装包成本高——用标准库实现：口令 `hashlib.scrypt`（加盐、参数随哈希存储），令牌为标准 JWT 格式的 HS256 签名，
  自写约 60 行并由测试锁住（签名、过期、算法字段、篡改）。不引入新依赖。
- **策略集中**：公开路径白名单与角色规则都写在 `core/deps.py` 的 `get_current_user` 里，所有路由仍挂这一个依赖
  （红线 5 字面不变：全路由挂插槽、不得绕过）。每次请求回库读取用户，停用或改角色立即生效。
- **角色**：admin（全部 + 用户管理）/ operator（全部业务读写，不能管用户）/ viewer（只读，所有非 GET 请求 403）。
  不单设 device 角色：模拟器和小车 `--field-id 0` 会自动建地块、作物，需要业务写权限，按 operator 账号登录；
  设备级凭据随 0007 P0 设备注册一起做。
- **采集端**：simulator 与 rover 通过 `--token` 或 `--username/--password`（及同名环境变量）认证，401 时用口令重登一次；
  未提供凭据时不带头（烟测的模拟服务器不要求认证）。
- **照片**：`/media` 静态目录仍公开——浏览器 `<img>` 无法携带 Bearer 头；照片 URL 是内容哈希，不可枚举。签名 URL 记技术债。
- **首个管理员**：不设默认口令。`python -m app.tools.create_user --username admin --role admin` 交互输入口令。
- **密钥**：`AUTH_SECRET` 环境变量；dev 环境为空时使用固定开发密钥并告警，非 dev 环境为空拒绝启动。

## 决策记录
- 编号决策 D15（登录认证与角色权限），B4 标注为被 D15 取代。
- 复核人、审批人等字段本期仍由前端提交（前端默认填当前用户姓名）；改由服务端按登录用户署名记技术债。

## 结果
- 后端：16 项认证测试（口令与令牌纯函数、白名单、登录成败、停用即失效、只读、自助改口令、用户管理、最后一个管理员、
  建号工具），其中一项按 OpenAPI 逐个匿名调用全部 89 个接口，除健康检查与登录外均为 401；另验证过「绕开 api_router
  挂的接口」会出现在 OpenAPI 且匿名 200，即该检查能抓住泄漏。既有业务测试经 `client` 夹具以管理员身份运行，全部通过。
- 采集端：rover 烟测新增 5 项（账号首次 401 登录一次、令牌直用、无凭据的可操作提示、口令错误、环境变量读取），
  同时覆盖 simulator 客户端。
- 端到端（新建库 → 迁移 0014 → 建号）：模拟器无凭据时在第一个受保护接口给出登录提示；只读账号建档被 403 拒绝；
  操作员账号跑通建档→上传→分析→建议全流程。
- 前端：未登录访问任意页面跳登录页并在登录后回跳；管理员可见「用户管理」；只读账号删除作物时提示「只读账号不能修改数据」，数据未变。
- 遗留见技术债台账：照片目录公开、署名由前端提交、登录限流、只读账号仍显示写按钮、设备级凭据。
