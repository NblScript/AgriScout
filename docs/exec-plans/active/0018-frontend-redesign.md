## 背景
0014、0015 的功能都是加在小麦大田时期的页面旁边，用户第一眼看到的仍是大田那一套。代码现状（2026-10-03，main `eaeacf0`）：
- 导航（`App.vue` 侧栏）是 10 个平铺入口：数据总览、系统状态、地块、作物、种植记录、设备、规则修订审批、研究闭环、巡检任务、用户。
  株档案和单株时间线不在导航里，只能从地块页按钮进入；0015 的计划页 `/fields/:id/plan` 也是同样的入口方式。
- 巡检回放（`PatrolDetailView.vue`，791 行）以 GPS 轨迹地图为主，详情卡是「生育期 / 长势 / 绿色覆盖（NDVI 代理）/ 风险分」，
  病斑框文案写死「锈病」，每个点只展示一张照片。大棚里坐标是估算值，叶背、补拍次数、图像质量在这里都看不到（只在单株时间线里有）。
- 数据总览 `/screen`（`BigScreenView.vue`，590 行）展示「巡检地图 · 轨迹与长势」「沿线环境 · 气温 / 土壤湿度」，没有每株状态、环境风险和待确认。
- 研究闭环页按「观察区域」展示，大棚地块已按株号关联，但文案和列仍是网格口径。
- 标题是「巡知 · 农田巡检与复巡决策平台」；视觉只有 `styles/theme.css` 25 行的主色覆盖，各页样式散落在 scoped CSS 里，间距、字号、卡片样式不统一。
- 技术栈：Vue 3 + Element Plus + ECharts + Leaflet + Pinia，无 CSS 框架，无前端单测框架。

目标：打开系统第一眼就是「今天哪个棚风险高、哪些株要补拍、哪些株等人确认」；视觉做到专业、克制、耐看，答辩投影也清楚。

## 设计（已定，照此实现；视觉方向以「决策记录」里人确认的为准）
1. **视觉方向（默认：浅色专业）**：
   - 全站浅色，背景用带一点绿调的浅灰，内容放白色卡片；只有一个品牌色（沉稳绿，沿用 `#15803d` 色系，可微调）；其余信息靠层级、留白和对齐表达，不用渐变、发光、3D。
   - 参照对象：成熟 SaaS 后台的克制风格（大量留白、细描边、小圆角、单层浅阴影、数字等宽对齐）。展示屏用同一套视觉放大，不另做深色炫酷风（投影仪下浅色更清楚）。
2. **设计令牌**（新文件 `src/styles/tokens.css`，纯 CSS 变量，不加 SCSS 依赖）：
   - 中性色 10 阶、品牌色 10 阶；语义色 success / warning / danger / info。
   - **株状态色**（全站唯一来源）：健康、早期、明显、未知四色；**任务类型色**：确认、补拍、全覆盖、抽查四色，与状态色可区分。
     两组颜色都要过色盲模拟检查，且不能只靠颜色区分（网格格子另带角标或图例里的形状，表格里带文字）。
   - 间距 4px 基数（4/8/12/16/24/32/48）；圆角 6/8/12；阴影最多两档；字号 12/13/14/16/20/24/30，行高配套；数字统一 `tabular-nums`。
   - 字体用系统中文字体栈（PingFang SC / Microsoft YaHei / Noto Sans SC），不加网络字体（场地可能无网）。
   - `styles/theme.css` 改为把 Element Plus 的 `--el-*` 变量全部映射到令牌；各页 scoped CSS 里的硬编码颜色、间距改用令牌。
3. **布局外壳与导航**（`App.vue` 拆成 `layouts/AppShell.vue` + 侧栏、顶栏组件）：
   - 侧栏分组（组名小字灰色）：
     - 工作：工作台、待确认（带未完成数角标）、大棚与地块、巡检记录；
     - 研究：研究闭环、规则修订审批；
     - 管理：作物、种植记录、设备、用户（仅管理员）、系统状态。
   - 顶栏：页面标题 + 面包屑（大棚详情、单株时间线要能一键回到所属大棚）；右侧当前地块切换器（记住上次选择，用 localStorage，读写包 try/catch）、用户菜单。
   - 标题改为「巡知 · 设施大棚病害主动巡检平台」（以 D16 口径为准）。
   - 新增通用组件（`components/ui/`）：`PageHeader`、`StatCard`（指标 + 变化 + 说明）、`StateTag`（株状态）、`TaskTypeTag`、`EmptyState`、`SectionCard`、`QualityBadge`（iq-rule-v1 的 ok / reasons）。
   - 登录页按新视觉重做，保留现有登录逻辑和过期提示。
   - 根路由 `/` 改为重定向到 `/home`（工作台）。
4. **页面（阶段 B）**：
   - **工作台 `/home`**（新首页）：
     - 每个大棚一张卡：今日环境风险（`env_index`，为 None 时明确显示「环境数据不足」，不得显示成低风险）、是否有清晨窗口、
       今日计划四类条数、待确认数、株状态分布条；点卡片进大棚详情。
     - 下方「待我确认」前 10 条和「最近巡检」5 条。大田地块单独收在一行，只显示最近巡检。
   - **大棚详情 `/fields/:id`**（新），标签页：
     - 概览：「垄 × 株」状态网格（见设计 6）+ 环境近 72 小时摘要 + 最近一次计划摘要；
     - 巡检计划：0015 的 `PlanView` 挪进来套新样式；
     - 株档案：现 `UnitsView` 挪进来；
     - 环境：0015 的环境曲线；
     - 巡检记录：该地块的巡检列表。
     - 0014/0015 的旧路由 `/fields/:id/units`、`/fields/:id/plan` 保留为子路由或重定向，已有链接不能失效。
     - 大田地块进这个页时只显示概览（地图 + 最近巡检）和巡检记录。
   - **单株时间线 `/units/:id`**：顶部状态卡（StateTag、来源、把握程度、最后合格叶背时间）+ 确认操作；照片按日期分正面 / 叶背两列，补拍次数和 QualityBadge 并排显示。
     **这一页和待确认页要能在手机宽度（≥375px）上用**：人在棚里拿手机确认。
   - **待确认 `/confirm`**（新）：列出所有未完成的「确认」类任务（`RevisitTask` 类型 label），按分数排序，显示株号、所属大棚、原因摘要、最近叶背缩略图；
     点开在侧滑面板里看照片并直接选「健康 / 早期 / 明显 / 其他」提交，提交后自动跳到下一条。提交方式沿用 0015 时间线「确认状态」，不另造接口。
   - **巡检回放 `/patrols/:id`** 按地块设施类型分两种模式：
     - 大棚模式：左侧用状态网格标出本次巡到的株，下方按巡检顺序逐株播放；右侧单株卡显示本点所有照片（按正面 / 叶背、第几次拍分组，带 QualityBadge 和不合格原因）、
       分析结果、所属株链接；不显示长势、NDVI、生育期星级。
     - 大田模式：保留现有地图、轨迹、长势和全部功能，只换新样式。
     - 病斑框文案按 `disease_detections[].type` 映射显示（映射表放 `types.ts`），去掉写死的「锈病」；问一问、AI 报告、农事建议三块保留，改成可折叠的分区。
     - 791 行的单文件拆成大棚模式、大田模式、照片面板、建议 / 报告 / 问一问几个子组件，拆分后单文件不超过 400 行。
   - **研究闭环**：列名「观察区域」改为「观察对象」，株号可点进单株时间线；其余功能不变，套新样式。
   - **展示屏 `/screen`**：工作台的全屏放大版，用同一组组件，字号和间距放大一档，可轮播各大棚；去掉「轨迹与长势」「土壤湿度」。
   - 其余页面（作物、种植、设备、规则修订、用户、系统状态、巡检列表）：只换外壳、`PageHeader` 和表格样式，业务逻辑不动。
5. **后端汇总接口（可选，仅当工作台需要）**：`GET /stats/greenhouses`，只读，按大棚返回 `{field_id, name, facility_type, env_index, env_coverage, morning_window, plan_counts{confirm, reshoot, coverage, random}, open_confirm, state_counts{healthy, early, symptomatic, unknown}, last_patrol_at}`；
   内部只调用 0015 的现有服务函数，不复制业务逻辑；带 pytest。`test_auth` 自动检查匿名 401。若前端逐个地块调用 0015 接口已足够快（10 个棚以内），可以不做，在「决策记录」里写明。
6. **「垄 × 株」状态网格组件**（`components/PlantGrid.vue`）：
   - 输入：株列表（key、row_no、seq、状态、今日任务类型、上次叶背是否合格）；行 = 垄，列 = 株序号；解析不出垄号的自定义键放在末尾「未编号」一行。
   - 格子填状态色；今日有任务的格子加任务类型色的描边；上次叶背质量不合格的加小角标。悬停显示株号、状态、原因；点击进单株时间线。
   - 用 CSS Grid 或单个 SVG 渲染；3000 株时首屏渲染不超过 300ms（开发机，生产构建），超过就改用 canvas。
   - 图例常驻；支持只看某种状态 / 某类任务的筛选。
7. **工程约定**：
   - 不加 UI 组件库、CSS 框架、图标库以外的运行时依赖；图标继续用 `@element-plus/icons-vue`。
   - 类型继续以 `types.ts` 为单一事实源；新接口在 `api/index.ts` 里加 api 对象方法。
   - 页面宽度适配：主要页面 1280–1920 桌面宽度；单株时间线和待确认页额外支持 375px 手机宽度；不出现整页横向滚动。
