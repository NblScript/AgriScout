# 0013 · 温室方向软件线：风险驱动的闭环主动采集

## 状态
2026-10-03 建档，未开工。方向见决策 D16；场地（组员照片中的河南塑料大棚）在核实中，试拍前只做不依赖场地的软件工作。
开工顺序：WP1 → WP2 → WP3 → WP4；WP5、WP6 等试拍拿到真实照片后再投入。

## 背景

**要解决的问题**：设施大棚（日光温室、塑料大棚）里，黄瓜霜霉病等叶部病害的早期征兆和确诊特征集中在**下部叶片的叶背**，
部分征兆只在**清晨高湿时**明显。人工要逐株翻叶，做不到每天每株；环境预警只能说「今天风险高」，定位不到植株；
散户大棚过道窄、路况差，固定方式拍摄的设备拍不全、拍不好。第一版只做黄瓜霜霉病。

拆成三个依次递进的具体问题，对应三个创新点（总创新：**风险驱动的闭环主动采集**，怎么拍由风险和拍摄质量实时决定）：

| 具体问题 | 创新点 | 降低的成本 |
|---|---|---|
| 看不到 | 一、带质量反馈的叶背主动采集：停车后低位按预设仰角拍叶背并补光，逐张判断叶背是否露出、有无遮挡、是否清晰，不合格补拍 | 普通 RGB + 树莓派 + 云台，不用高光谱；不改造大棚 |
| 认不出 | 二、同株时序追踪：编码器 + 吊线或立柱标签，把每天的图像对齐到同一株，给出每株状态（健康 / 早期 / 明显）和把握程度 | 不用轨道、不用 RTK |
| 何时看、看哪里 | 三、环境风险驱动的采集与确认分配：冠层温湿度、结露 + 每株状态，决定巡检时机、补拍对象、推给人确认的对象；确认结果写回时间线 | 人只确认被推送的植株 |

早期确认是闭环的产出：疑似早期的植株 1–3 天内跟踪确认，标注口径沿用农大 / 北大 2026 的三阶段分级（引用，不作为创新点）。

**已有先例**（决定了哪些不能当创新点）：温室黄瓜叶部病害巡检机器人专利 CN221048423U（轮式、升降、云台相机、识别、地面标志定位，
未涉及叶背仰拍）；Viewnetic 美国专利 US11483471B2（补光 + 向上成像拍叶背，看小虫）；农大 / 北大 Frontiers 2026（环境引导的视觉-时序早期检测，
三阶段分级，冠层上方俯拍 + 人工补拍，无主动采集）；Ecoation（风险地图给人看）。

**场景约束**（影响软件设计）：
- 塑料大棚北方只种春秋两茬：春茬约 4 月中下旬定植、6 月底到 7 月初拉秧；秋茬 8 月定植、生长期 100 天以上。冬季只有日光温室。
- 塑料大棚昼夜温差大，夜间结露加重霜霉病（发病适宜约 15–25℃、湿度 85% 以上），环境风险信号更有用。
- 散户塑料大棚多半没电、没网：采集端要能离线工作，补拍判断要在车上算。
- 过道有泥、软管、采收筐：小车先承诺规整大棚（适用条件待实测）；散户大棚的退路是同一套方法装在手持杆式或手推式设备上。

## 决策记录
- 已定（D16）：方向调整为设施大棚黄瓜霜霉病的风险驱动闭环主动采集；取代基线 B3（首批作物小麦）。
- 已定（2026-10-03）：范围包含塑料大棚。
- 已定（组员意见）：创新点按依赖顺序排列，一采集 → 二同株追踪 → 三风险分配，避免二引用三的结果；每个创新点写明降低的成本，不单列成本创新。
- 已定：风险**不用来减少巡检**，用来分配补拍时间和人工确认时间；保留低频全覆盖和随机抽查，避免漏掉模型没注意到的新病灶。
- 已定：硬件相关部分（云台、补光、编码器、标签识别）先写接口和假实现，硬件定型后再接真驱动。
- 已定：模拟器结果只证明流程跑通，不作为效果证据（病害规律是按设计放进模拟器的）。
- （待定）补拍判断放在车上：塑料大棚多无电无网，倾向车上计算（规则版质量判断在树莓派上跑；模型版需要 TX2 上车）。
- （待定）是否新建株档案表 `observation_units`（大棚、垄、株序号、标签编码、启用状态）：建议建，「每株状态」需要一个落点。
- （待定）标签用二维码还是 AprilTag；贴在吊线、立柱还是垄头。
- （待定）适用条件（过道最小宽度、地面平整度），等实地测量。
